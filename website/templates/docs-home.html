How the parts fit together

Your browser is where you author the project. The Raspberry Pi runs the application, bridge, game services, audio and displays. A USB data cable connects it to the ESP32-S3, which reads physical inputs, handles supported real-time output behaviour and enforces output safety limits.

Browser → Raspberry Pi → USB bridge → ESP32-S3 → inputs and outputs. Input reports travel back through the controller and bridge. Events report what happened; Rules decide what happens next. Some rules run on the Pi and supported hardware rules run on the ESP, so save and sync are separate steps.

Start with a small, observable rule

Use an input you can identify in the event log. Give its rule a clear name, choose the observed trigger and add a non-coil action you can verify. Test it once, confirm the result, then build on it.

Start with coils disconnected

Never connect a coil, lamp or other high-current load directly to a Pi or ESP GPIO. Use suitable drivers, power supplies, fuses and flyback protection for your actual circuit. Disconnect output power while wiring and keep a physical means of removing power available.

Firmware arming, watchdogs and pulse limits are safeguards; they do not make incorrect wiring safe. Read the Hardware guide before testing outputs. Software previews cannot verify electrical safety.
