# Hyrule — The Hero of Time

An Ocarina of Time-inspired Godot 4.6 backglass presentation for pinballctl.
Five newly generated painterly environments, original synthesized sound cues,
procedural animated emblems and twenty presentation sequences are included.
The cinematics run in Godot; there are no prerecorded films or external video dependencies.

## Run and preview

From the repository root:

```sh
godot --path backglass -- --preview
```

Or open `backglass/project.godot` in Godot and run the project. Select opens the
main menu; **Preview theatre** or **F1** opens the scene gallery.

| Control | Action |
|---|---|
| Left / Right (cabinet flippers) | Move through menu, destinations or preview scenes |
| Space (desktop Select) | Select / play / return to gallery |
| Flippers + Select | Navigate to Back; preview playback Select returns to gallery |
| F1 | Enter / leave preview, restoring the live display state |
| P, in preview | Pause / resume animation |
| R, in preview | Replay the current scene |
| A, in preview | Toggle automatic cycling through all scenes |
| Left / Right, in preview initials | Change letter; Select confirms each letter |

Mouse clicks also select menu items, map destinations, settings and gallery scenes.
In live initials entry use Left / Right to change letters and Select to confirm.
Preview uses demonstration values, emits no machine events and never persists demo
scores. An incoming controller state immediately leaves preview. Preview initials
can be exercised without affecting saved records.

## Included presentation

- A 44-second, seven-shot attract film: Hyrule dawn, map journey, new Master Sword
  close-up, Ganon's castle, assembling Triforce, title reveal and local chronicles.
  Includes crossfades, camera moves, mist, leaves, embers and an original timed score.
  Select interrupts every shot immediately; reduced motion uses stationary shots.
- Main menu, six-destination Hyrule map, instructions, volume and reduced-motion settings.
- Gameplay score, player, ball, rupees, bonus multiplier, quest progress and multiball HUD.
- Skill shot, skill success, skill missed; bonus tally with skip to final value.
- Triforce multiball intro, jackpot, super jackpot, ball saved, extra ball.
- Quest complete, wizard mode, victory, ball lost, tilt warning and persistent tilt.
- Game over, three-character initials entry, top-five local chronicles.

Quick awards now use distinct entrance, impact and exit choreography. Bonus spins
in, counts for 1.65 seconds, punches the final amount and whips out within three
seconds. Jackpot zooms forward; skill-shot outcomes sweep sideways; ball-save
rises with a fairy trail; extra-ball pops; quest completion stamps in. Quick
notifications finish in 1.1–2.2 seconds. Multiball and major story moments retain
their longer cinematic timing. Reduced motion removes spinning, sweeps and impact
flashes while retaining readable content and the same duration.

Each sequence has a catalogued duration. Transient live sequences return to gameplay;
game over offers initials for a qualifying score, otherwise returns to attract.
Tilt, gameplay, records and initials have no automatic timeout. Preview plays quick sequences through to their gameplay return, then holds with
a replay hint. Longer sequences hold unless autoplay is enabled. Transitions can always be interrupted
without stale timer callbacks changing the new screen.

Artwork is in `zelda/assets/`; animation and UI geometry are generated by Godot.
Audio is original synthesized material, reproducible with
`python backglass/utils/generate_audio.py`. Font selection uses available Georgia,
Noto Serif or DejaVu Serif, with Godot fallback; install Noto Serif on the Pi for a
consistent serif presentation. No Nintendo artwork or soundtrack files are bundled.
The earlier carousel example is retained at `scenes/main.tscn` and `scripts/main.gd`.

## Controller integration

This is a **presentation**, not a Zelda rules engine. Shot switches, scoring,
quest eligibility, ball accounting and hardware safety remain in pinballctl/ESP.
Quest names and objective copy in `zelda/catalog.gd` are suggested game design;
map the corresponding rules for your machine. Every destination is selectable;
there is no implied controller-side unlock policy.

Export and upload the pack through Media; choose **`res://zelda/main.tscn`** as
its entry scene. Use the existing runtime inputs (`ui_left`, `ui_right`,
`ui_accept`, `ui_cancel`) for flippers, Select and optional controller Back. The project also accepts
`pinballctl_input_key(key_name, phase)` and direct `pinballctl_input_action(action)`.

Selecting a destination emits:

```json
{"name":"BACKGLASS_START_REQUESTED","params":{"quest":0,"quest_name":"Korok Forest"}}
```

The map waits for the controller; selecting a destination never starts hardware.
Initials entry emits `BACKGLASS_INITIALS_SUBMITTED` with `initials` and `score`.
The `mode_selected(mode_name, mode_index)` signal is also available locally.

### Live state

The host's optional `pinballctl_text_values(values)` hook supplies existing text
values to imported scenes, including nested scenes. Existing `{{TOKEN}}` labels
continue to work. Send a JSON string as `BACKGLASS_STATE` through `UPDATE_TEXT`:

```json
{"cmd":"UPDATE_TEXT","text":{"key":"BACKGLASS_STATE","value":"{\"screen\":\"gameplay\",\"score\":1248500,\"player\":1,\"ball\":2,\"quest\":0,\"progress\":2,\"multiplier\":3,\"rupees\":42,\"multiball\":false}"}}
```

Or call `pinballctl_state(dictionary)` directly from your own Godot integration.
Updates merge numeric fields; omitted fields retain their current value.

| Field | Meaning |
|---|---|
| `screen` | One of the IDs below; unknown IDs are ignored |
| `score`, `bonus`, `award`, `rupees` | Nonnegative controller totals; bonus/award animations never add to score |
| `player`, `ball`, `multiplier` | Positive integers, bounded to 1–99 |
| `quest` | 0–5, ordered Korok, Death Mountain, Lake Hylia, Time, Spirit, Ganon |
| `progress` | Completed objective markers (three displayed) |
| `multiball` | Boolean controlling the persistent gameplay HUD |
| `event_id` | Unique occurrence identifier to replay the same screen exactly once |

Use a fresh `event_id` for each award, for example `jackpot-24`. Repeating the last
ID does not restart an animation. Without an ID, a screen changes only when it
is different from the current screen. For score-only updates, omit `screen`.
Send `multiball:true` at multiball start and `false` when it ends.
Malformed JSON and invalid field types are ignored; numeric values are bounded.

Screen IDs:

```text
attract gameplay skill_shot skill_success skill_missed bonus multiball jackpot
super_jackpot ball_saved extra_ball quest_complete wizard victory ball_lost
tilt_warning tilt game_over initials records
```

For scene-only triggers, send an existing runtime input action such as
`backglass_bonus`, `backglass_multiball` or `backglass_game_over`. These use current
state; update amounts first. `backglass_preview` toggles the gallery. These are
Godot media runtime commands, not ESP serial commands; frames-only transport and
hardware safety are unchanged.

### Persistence

Volume, reduced motion and the top five records live in
`user://hyrule_backglass_v1.json` in Godot's application user directory. Under the
media host, this is the host's user directory. Corrupt preferences are ignored;
a write failure is logged. Scores are local to the display, not a machine-wide
leaderboard. The controller decides when to present a final player score; for a
multiplayer game it should send each qualifying player's initials screen explicitly.

## Export and validation

```sh
# Import assets on a clean checkout first.
godot --headless --path backglass --editor --import --quit
# PCK is platform-independent; no Linux executable is produced.
godot --headless --path backglass --export-pack Linux /absolute/path/hyrule.pck
# Test presentation behaviour without writing preferences.
godot --headless --path backglass --script res://zelda/tests/smoke.gd -- --test
# Verify the host state hook and existing text-label compatibility.
godot --headless --path src/godot --script res://tests/scene_state.gd
# Capture all screens from the real renderer (requires a graphical session).
BACKGLASS_CAPTURE_DIR=/absolute/path/captures godot --path backglass \
  --script res://zelda/tests/capture.gd -- --test
```

Exports exclude the old carousel, tests and utilities. New resources are namespaced
under `res://zelda/` so loading the pack cannot replace the host's scripts.
The canvas is authored at 1920×1080 and letterboxes other aspect ratios. OpenGL
Compatibility rendering is selected for the Pi. Target-device frame rate and
physical cabinet input mapping must be validated on your hardware.

To capture the short animation timelines at 20 fps for visual review, run
`BACKGLASS_CAPTURE_DIR=/absolute/path/frames godot --path backglass --script res://zelda/tests/capture_motion.gd -- --test`.

Capture all film shots and transitions with
`BACKGLASS_CAPTURE_DIR=/absolute/path/storyboard godot --path backglass --script res://zelda/tests/capture_attract.gd -- --test`.

## Keep the application in sync

Run `.venv/bin/python backglass/utils/sync_application.py` from the repository after changing this pack or its media. It imports and exports the current source and updates the same 25 application scene IDs and shared pack in `src/instance/media`. Application-managed runtimes are stopped to clear cached resources; launch the desired scene from Media afterwards.

The initial replacement uses `--replace-existing`: existing media assets/cache and configuration are backed up under `.local/media-backups/`, the old library/scenes are removed, and the default becomes Hyrule Attract. Fonts and display configuration are retained. Subsequent syncs preserve other library entries. Runtime data and backups remain local, outside Git.

Each entry in `zelda/entries/` opens its named screen immediately. The installed mappings reuse the configured Left Flipper Button, Right Flipper Button and Launch Button (Select), on CLICKED events. Change Select in Media input mappings if a different cabinet button is desired. Enter and Escape are ignored. Use Left/Right and Space for desktop testing; F1 opens preview, P pauses, R replays and A cycles. Back is selectable on the quest map and gallery; Select returns from instructions, records and preview playback.
