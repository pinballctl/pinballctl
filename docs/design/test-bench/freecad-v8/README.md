# Native FreeCAD revision 8

Open **test-bench-v8.FCStd** in FreeCAD 1.1 or newer. This is the editable CAD document: its sketches, driving dimensions, extrusions, fillets and boolean features are saved inside the file. Opening or editing it does not require CadQuery or running a Python script.

The migration preserves the existing `cad-v8` geometry. It does not redesign the enclosure or replace the approved revision 8 visual mockup. Manufacturing limitations remain unchanged.

## Editing

- Expand **Test bench — revision 8** to find the named finished components. These are native assembly links to the modelling features.
- Use the tree search to find **Base outline — width and depth**, **Lid outline — width and depth**, **Start button mounting hole — radius**, **Breadboard lid opening — width and depth**, or **Breadboard tray recess**. Double-click a sketch to edit its named driving constraints in Sketcher. Rectangle constraints are `Width0` and `Depth0`; circular profiles use `Radius0`.
- Extrusion lengths and edge-fillet radii are native feature properties in the Data panel. Rounded rectangular profiles use fully constrained tangent arcs, driven by the original width/depth sketches, so resizing does not depend on corner edge references. Profile placement controls location and orientation.
- Select **View settings — lid angle** and change **Lid Angle** from 0° to 75° to open the assembly. The native placement expressions rotate every lid-mounted part about the same pivot. Leave 0° for the saved closed view.
- Recompute after editing. The model has separate dimensioned profiles, not a single global resizing parameter: changing the overall footprint may require adjusting related profiles and component positions. Large edits can require repairing edge references, as with other fillet/boolean histories.

The lettering uses retained solid glyph outlines so that fonts cannot change the existing appearance. It is the only imported geometry; changing lettering requires replacing those outlines. The other geometry is generated by native features. Purchased components are dimensioned envelopes, not supplier-certified models.

## Preview workflow

`export_previews.py` opens the **saved FCStd file**, evaluates the 0° and 75° positions and tessellates its final assembly parts. `render_previews.py` renders those meshes with VTK. Neither imports nor runs the old CadQuery model. Save edits in FreeCAD before exporting previews.

On this macOS installation:

```sh
PYTHONPATH=/Applications/FreeCAD.app/Contents/Resources/lib /Applications/FreeCAD.app/Contents/Resources/bin/python docs/design/test-bench/freecad-v8/export_previews.py
/tmp/pinballctl-cad-env/bin/python docs/design/test-bench/freecad-v8/render_previews.py
```

The second command requires VTK. Render outputs are `docs/media/test-bench-freecad-v8-{closed,open,top}.png`. Intermediate meshes are placed in `/tmp/pinballctl-freecad-preview`. `preview-provenance.json` records the saved FCStd hash and each rendered image hash; the renderer rejects meshes exported from an older version of the document.

## Migration and checks

`capture_history.py`, `create_document.py` and `finish_document.py` record the one-time migration from the previous solid model; they are not required to use the FCStd. Re-running them would overwrite native edits. The capture uses the isolated CadQuery environment; creation uses FreeCAD's Python; finishing uses its GUI libraries for saved colours and labels. Intermediate reference geometry is kept under `/tmp/pinballctl-freecad-history`.

`conversion-checks.json` records per-operation geometry comparisons. `native-validation.json` records reopening the saved file, fully constrained sketches, closed/open shape comparisons against all original assembly parts, and native dimension edit/revert tests. `validate_document.py` performs these migration comparisons while the captured reference geometry is available.

This remains a design-review model. Component retention, optical cavities, wiring, populated lid clearances, print tolerances and fatigue still require engineering and prototype testing. A native file does not constitute fabrication approval.
